# Capability: Execute Query

## What It Does
Receives a sanitised SQL statement, opens the appropriate database (per-session SQLite in Phase 1, PostgreSQL MSSQL mirror in Phase 2), executes it safely via parameterised `sqlalchemy.text()`, and returns the rows, row count, and any error — without modifying any data.

## Inputs

| Input | Type | Source | Required |
|-------|------|--------|----------|
| `sql_text` | `str` | `generate_sql_node` output | Yes |
| `sqlite_path` | `str \| None` | `ingest_csv_node` output (Phase 1) | Yes when `datasource="sqlite"` |
| `datasource` | `str` | `AgentState` — set by runner from environment | Yes |
| `AGENT_DATABASE_URL` | `str` | Env var (Phase 2 PostgreSQL mirror) | Yes when `datasource="mssql_mirror"` |
| `AGENT_MAX_QUERY_ROWS` | `int` | Env var (default 10 000) | No |

## Outputs

| Output | Type | Destination |
|--------|------|-------------|
| `query_rows` | `list[dict]` | `AgentState` — consumed by `format_answer_node` |
| `row_count` | `int` | `AgentState` — shown in UI and audit log |
| `sql_error` | `str \| None` | `AgentState` — on DB error, routes back to `generate_sql_node` (retry) or to `handle_error_node` (max retries reached) |

## External Calls

| System | Operation | On Failure |
|--------|-----------|------------|
| SQLite (Phase 1) | `create_engine(f"sqlite:///{sqlite_path}").execute(text(sql_text))` in a context-managed connection | Catch `OperationalError`, `ProgrammingError`, `DataError`; set `sql_error` with DB error text (truncated to 1 000 chars) |
| PostgreSQL (Phase 2) | `create_engine(AGENT_DATABASE_URL).execute(text(sql_text))` | Same as above |

## Business Rules

- **Read-only enforcement:** The node pre-validates `sql_text` by scanning for DML keywords (`INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `CREATE`, `MERGE`, `TRUNCATE`, `EXEC`, `EXECUTE`, `CALL`) before execution. If found, `sql_error = "Only SELECT queries are permitted"` is set and execution is skipped.
- **Row truncation:** If `len(rows) > AGENT_MAX_QUERY_ROWS` (default 10 000), only the first 10 000 rows are kept in `query_rows`; `state["truncated"] = True` is set. `row_count` still reflects the true count (from `len(rows)` before truncation). `format_answer_node` adds a `<truncation>` caveat in the answer when `truncated=True`.
- **SQL injection safety:** The SQL string is passed to SQLAlchemy via `text(sql_text)` — parameter-binding is not needed because the SQL is entirely generated by the LLM and is not combined with user input via string concatenation.
- **Timeout:** A 30-second query timeout is applied at the SQLAlchemy connection level (`connect_args={"timeout": 30}` for SQLite; `statement_timeout = '30s'` SET command for PostgreSQL connections). Queries exceeding 30 seconds are cancelled and produce `sql_error = "Query timed out after 30 seconds"`.
- **Path safety for SQLite:** `sqlite_path` must be a path under `data/sessions/`. The node resolves to an absolute path and validates the directory prefix before opening the engine; any path outside the allowed directory produces `sql_error = "Invalid SQLite path"`.
- **No DML side-effects:** Even if the sanitisation check were bypassed, SQLite in read-only mode (Phase 1) or a read-only PostgreSQL user (Phase 2) prevents writes. The PostgreSQL user for the agent account is granted only `SELECT` on the mirror schema tables.

## Success Criteria

- [ ] `SELECT COUNT(*) FROM data` returns `{"rows": [{"count": N}], "row_count": 1}` for a known fixture CSV
- [ ] A query returning 0 rows provides `query_rows=[]`, `row_count=0`, `sql_error=None`
- [ ] A query with an invalid column name (`SELECT foo FROM data`) produces `sql_error` containing "no such column: foo" and `sql_attempts` increments on the returning edge
- [ ] A query returning 15 000 rows is truncated to 10 000 with `truncated=True`; `row_count=15000` is still correct
- [ ] A `DROP TABLE data` SQL is rejected before execution with `sql_error="Only SELECT queries are permitted"` and the table is untouched afterward
- [ ] The 30-second timeout on a `SELECT pg_sleep(60)` (Phase 2) raises a timeout error caught as `sql_error`
